# 💡 DICAS.md — SpendWise (Welcome Page + UI/UX + Lógica)

## 🎯 Objetivo deste documento

Este ficheiro não é código — é o teu **guia estratégico** para construir uma welcome page e um mini-app que parecem produto real.
Segue estas dicas para aumentar as tuas chances de ficar no **top 5**.

---

# 🧠 🏆 MENTALIDADE DE PROJETO

* Não estás a fazer “um trabalho escolar”
* Estás a simular **um produto real**
* Menos features + mais polimento = melhor resultado

---

# 🧱 📐 ESTRUTURA DA WELCOME PAGE

## Ordem recomendada:

1. Hero (header)
2. Benefícios
3. How it works
4. CTA final
5. Footer

👉 Nunca misturar tudo — cada secção deve ter espaço e propósito

---

# 🎯 HERO (PRIMEIRA IMPRESSÃO)

## O que deve acontecer:

* O utilizador entende o app em 3–5 segundos

## Dicas:

* 1 título forte (curto)
* 1 frase explicativa
* 1 botão claro

## Evita:

* textos longos
* múltiplos botões

---

# 🎨 UI — DESIGN QUE IMPRESSIONA

## 🎨 Cores (mantém consistência)

* fundo escuro → mais moderno
* 1 cor principal (verde ou azul)
* 1 cor de erro (vermelho)

👉 Não usar muitas cores diferentes

---

## 📏 Espaçamento (muito importante)

* usar bastante espaço entre secções
* padding mínimo: 20px
* margem entre blocos: 40px+

👉 espaço = design premium

---

## 🧱 Layout

* centralizado
* largura máxima (não full width sempre)
* usar “cards”

---

## 🌫️ Sombras e profundidade

* sombras leves dão efeito profissional
* não exagerar

---

## 🔘 Botões (CRÍTICO)

* sempre iguais no site inteiro
* grandes e clicáveis
* com hover

👉 o botão é o foco visual

---

# ⚡ UX (EXPERIÊNCIA DO UTILIZADOR)

## ✔ Clareza

* o utilizador deve saber:

  * o que é
  * o que faz
  * o que clicar

---

## ✔ Simplicidade

* menos opções = melhor experiência

---

## ✔ Feedback visual

* ação → resposta

  * botão clicado muda
  * ação confirmada

---

## ✔ Fluidez

* nada deve parecer travado ou confuso

---

# 🧠 LÓGICA (PARA NÃO PARECER AMADOR)

## ✔ Organização

* separar responsabilidades
* funções com nomes claros

---

## ✔ Fluxo mental

Sempre pensar:

```plaintext
dados → processamento → interface
```

---

## ✔ Evitar bugs

* validar inputs
* tratar valores vazios
* garantir números corretos

---

## ✔ Atualização de UI

* sempre que dados mudam → atualizar interface

---

# 💾 LOCALSTORAGE (USO INTELIGENTE)

## ✔ Guardar sempre após mudanças

* adicionar
* remover

---

## ✔ Nunca confiar direto no storage

* usar array como fonte principal

---

## ✔ Carregar ao iniciar

* garantir persistência

---

# 🎯 BENEFÍCIOS (SECÇÃO)

## ✔ Regra:

* máximo 3 a 4 itens
* cada um curto

## ✔ Foco:

* resultado para o utilizador
* não funcionalidades técnicas

---

# 🔄 HOW IT WORKS

## ✔ Estrutura:

* 3 passos simples

## ✔ Linguagem:

* clara
* sem termos técnicos

---

# 🚀 CTA FINAL

## ✔ Deve convencer

* repetir ação principal

## ✔ Frases boas:

* “Começar agora”
* “Controlar minhas despesas”

---

# 🦶 FOOTER

## ✔ Simples

* nome do app
* ano
* frase curta

## ✔ Não complicar

* não precisa links complexos

---

# 🧪 TESTES (ANTES DE APRESENTAR)

* layout não quebra
* mobile funciona

---

# 📱 RESPONSIVIDADE

# 🔥 DETALHES QUE DIFERENCIAM
